## 1. 三支视频解析（设计输入）

解析方法：B 站公开接口取元数据（三支视频均无 CC/AI 字幕）→ 下载视频流按 8 秒逐帧抽帧共 98 帧、读取画面 PPT → 与作者公开文字稿逐条交叉核对。抽帧索引图保存在 `assets/frames/`。

### 1.1 《大模型怎样重塑企业级 IT 应用（上）》BV1wP411i7U6，04:27

- 未来企业应用 **5 个特性**：自然语言连续对话；AI 生成任务驱动业务服务；多模态认知与生成；跨源数据整合（**数据规范性制约智能准确性**）；复杂软件系统处理（一个请假意图要调度 CRM、考勤、核心 HR、OA、日历等多个系统）。
- 企业信息系统始终要解 **3 个问题**：业务流程自动化；业务决策智能化（**OLTP 与 OLAP 融合**）；人机交互人性化。
- 架构演进：**单体 → 服务化解耦 → 微服务 → 容器化**，这才使「AI 生成流程、调度业务能力」成为可能。
- GPT 三特点：更强推理；通用大模型 + 企业自有「小数据」精调/嵌入变成「企业通」；AI 生成任务、任务触发业务服务。AutoGPT 式**自治代理**是终极形态——「你就对机器喊一嗓子，剩下的都交给 AI」。

**→ 设计约束**：任务/工作流编排层、工具注册与调度、实时 OLAP 通道、统一数据口径治理、自然语言与多模态入口；AI 不直接写核心账，只能通过编排层调用服务。

### 1.2 《AI 将如何重塑 ERP？》BV1Fh4y1J7wQ，04:41

- 反对「在 ERP 之上自研数字化场景」：那需要企业自建数字化/数据/AI 企业级平台，大型企业或可，中型企业难以驾驭；应当**重塑软件本身**。
- **① 用户体验**：图像/语音识别、多模态融合、智能推荐，改变输入方式与人机界面。
- **② 作业、分析、智能一体化**：90 年代作业在线化 → 2000 年后数据仓库/BI 离线报表 → 实时在线分析 → AI 规律洞察与决策。
  - 采购三阶段：手工选供应商 → 图形报表分析行情/采购历史/供应商表现 → **AI 自动推荐供应商 + 基于博弈论的采购谈判助手**。
  - 业财一体化：传统靠实施期预设的「**平行记账**」把业务交易转成财务凭证，对业务标准化要求极高，被抱怨「不灵活」；新架构用 **AI 判断会计规则**而非预设规则。
- **③ 系统处理大数据**：从系统内封闭「小数据」走向数字化世界全域大数据，获得人力不及的实时智能。
- 结论：不是原有系统的功能增强，而是**业务流程再造**；ERP/CRM/HCM 在 AI 时代都值得重做一遍。

**→ 设计约束**：AI 原生而非外挂；流批一体实时数仓；采购与业财是首批场景；柔性规则判断必须与硬规则引擎双轨并行，并保留凭证可追溯。

### 1.3 《用不好 ERP 却信中台和阿米巴？（上）》BV1yz4y1x7jz，03:59

- ERP 是企业管理数字化工具的**集大成者**；本源是**科学管理（泰勒制）的数字化形式**，致力于提升生产力，而非仅仅是「业务流程管理」。
- 泰勒制：标准化作业量（铁锹 21 磅）、标准工具、标准动作、科学选拔工人、管理者/工人分工、双赢分配规则；产能不变下人数降 3 倍、日薪升 60%；是工业工程、TQM、精益、六西格玛、供应链管理的源头。
- 管理哲学差异：欧美偏「提升生产力」，中国企业更偏「改善生产关系」；家庭联产承包责任制带来「**经营大于管理**」，中式阿米巴实质是经营承包责任制，平台经济是所有权/经营权分离的第二次革命。
- 结论：多数中国企业基础管理标准化薄弱，**因而用不好 SAP 这类 ERP**，转而追逐中台、阿米巴等时髦概念。

**→ 设计约束**：主数据/编码/口径必须先标准化（否则 AI 准确性无从谈起）；用 AI 做柔性适配降低「一板一眼」的束缚；核算模型支持多维度经营单元（事业部/阿米巴）分摊，但总账仍强一致。

## 2. 六条设计公理

| 编号 | 公理 | 说明 |
|---|---|---|
| A1 | 稳定内核 + 智能外壳 | 账务/库存/订单是记录系统，强一致可审计，不由概率模型直接改写；AI 经受控 API 调用内核 |
| A2 | 标准化是智能的地基 | MDM、统一编码、指标口径、数据质量分必须先于 Agent 上线 |
| A3 | 作业与分析一体（HTAP） | Flink CDC 秒级入湖仓，实时经营分析嵌进作业界面，替代 T+1 报表 |
| A4 | 一切 AI 动作可追溯 | 建议→规则校验→人工审批→执行→凭证→审计，带引用、置信度、模型版本、操作人 |
| A5 | 面向失败设计 | 无单点、多副本跨 AZ、限流熔断、幂等、事务消息+对账、备份演练、混沌工程 |
| A6 | 兼容中式经营核算 | 支持按经营单元/项目/区域灵活分摊与单位时间核算，分摊结果回到统一总账 |

## 3. 六层总体架构

```
L1 接入与体验层      Web/移动/企微钉钉 · Copilot 自然语言 · OCR/语音 · 经营大屏
L2 流量治理与安全层  GSLB + 双AZ CLB · APISIX · OIDC/IAM(RBAC+ABAC) · WAF · Sentinel
L3 业务服务层        12 个 DDD 限界上下文（SpringBoot3 / Nacos / Sentinel / Seata）
L4 AI 与任务编排层   LLM网关 · Agent+Temporal · 工具注册 · Milvus RAG · Drools · AI治理
L5 数据与集成层      Kafka/RocketMQ · Flink CDC · Iceberg+Doris · MySQL/TiDB/Redis/ES/MinIO
L6 基础设施层        多 K8s 集群 · 同城双活+异地灾备 · OTel/Prometheus · GitOps · 等保三级
```

一次「AI 下采购单」链路：自然语言意图 → LLM 规划 → 规则引擎校验（预算/权限/合规）→ Temporal 持久化任务 → 采购/库存/财务/审批服务 → 凭证与审计。全程权限继承登录态、幂等键去重、每步 TraceID、高风险动作人工确认。

## 5. 高可用与容灾

- **拓扑**：GSLB → 同城 AZ-A / AZ-B 双活（各自网关、业务服务、AI 层、缓存/消息副本）→ 异地 DR 温备（异步复制 + 每日快照 + PITR）。
- **指标**：核心链路 SLO 99.99%（年停机 ≤52.6min），登录/下单/过账 P99<300ms；账务 RPO=0；同城 RTO<15min；异地 RTO≤2h / RPO≤5min。
- **切换时序**：T+0s 健康检查失败 → T+10s GSLB 摘除故障 AZ → T+30s B 区 HPA 扩容 → T+2min MGR 选主 → T+5min 消息幂等重放与四方对账 → <15min 恢复并复盘。
- **韧性清单**：Sentinel 限流熔断与热点参数；幂等键 + 指数退避；事务消息回查 + 死信队列；每日订单↔库存↔凭证↔流水对账；PITR 季度真实恢复演练；金丝雀发布自动回滚；Chaos Mesh 注入 AZ 故障/网络分区/主从延迟。
- **一致性分级**：总账/凭证/资金/库存占用 → 强一致 ACID；订单/采购/审批 → 秒级最终一致；报表/大屏 → 秒~分钟最终一致；AI 建议 → 弱一致可失效，降级到规则引擎。

## 6. AI 与数据治理

**六步闸门**：① 自然语言意图（绑定登录态/权限/TraceID）→ ② LLM 规划与白名单工具选择（不直连数据库）→ ③ 取数并强制注入引用与时间戳 → ④ 硬规则一票否决（预算、额度、权限、税码、借贷平衡、期间）→ ⑤ 高风险动作强制 Human-in-the-loop → ⑥ 执行、凭证、不可篡改审计并进入评测样本池。

**神经符号双轨**：LLM 做柔性判断（业务语义、合同文本、历史相似案例）；Drools/决策表做刚性校验；两者不一致或置信度低于阈值 → 自动转人工。

**数据治理先行**：五类主数据（物料、供应商、客户、组织、科目）统一编码唯一源；指标口径版本化；数据质量分与血缘，低质量数据禁止进入 RAG/训练集；Agent 检索继承用户 ABAC，敏感字段出库脱敏，提示词与 Token 全量审计。

**首批场景**：智能供应商推荐、博弈论采购谈判助手、AI 判断记账规则、自然语言问数（只读 Text-to-SQL）、全域异常洞察、白名单+额度内的受限自治代理。

## 7. 实施路线

| 阶段 | 周期 | 内容 | 验收 |
|---|---|---|---|
| 一 · 地基 | 0–3 月 | MDM、统一身份、K8s 双 AZ、网关/注册/消息底座、CI/CD 与可观测 | 主数据唯一源上线、故障注入演练通过 |
| 二 · 核心域 | 3–6 月 | 采购/销售/库存/总账/应收应付；事务消息 + 幂等 + 对账；Flink CDC | P99<300ms、对账差异率<0.01% |
| 三 · 智能层 | 6–9 月 | 模型网关、RAG、供应商推荐、问数、AI 凭证草稿（全部建议态） | 引用可追溯率 100%、越权拦截率 100% |
| 四 · 自治与演练 | 9–12 月 | 白名单+额度自治代理；双活真实切换、异地恢复、等保三级 | RTO<15min、RPO=0、季度演练报告 |

**主要风险与对策**：幻觉进账（硬规则+置信度闸门+强制复核）、主数据不统一（MDM 先行）、组织变革阻力（先 augment 不 replace，保留中式核算维度）、老系统迁移中断（双写+影子流量+按域灰度+可回滚）、双活脑裂（单元化按租户路由、写流量单元内闭环、DB 单主半同步）、模型/云锁定（模型网关抽象 + 私有模型 + 数据不出域）。

**设计取舍**：放弃「一套分布式库通吃」（复杂度换确定性）、放弃「AI 全自动」、放弃「异地双活」（同城双活 + 异地温备控成本）、放弃「大爆炸替换」（按域灰度）。
